# ClubFlow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build ClubFlow, a demo-ready web app for the Skyline Student Association that replaces spreadsheets, cash, notebooks and WhatsApp with one system for membership, event tickets with QR check-in, announcements, merchandise, fundraisers, expenses and a finance ledger.

**Architecture:** A single Express API (`backend/`) backed by Neon PostgreSQL through Prisma, organised into modules (routes, controller, service, schema). Business rules live only in services, and every money movement writes one row to the `transactions` ledger, which is the only source for finance numbers. A React + Vite + Tailwind SPA (`frontend/`) talks to `/api` through one axios instance. It has public, member and admin areas guarded by a role-aware route.

**Tech Stack:** Node 24, Express 4, Prisma 5 (or the latest stable), Neon PostgreSQL, zod, jsonwebtoken, bcryptjs, helmet, cors, express-rate-limit, multer, nodemailer, node-cron, qrcode (not needed if the QR is drawn on the frontend), node:test + supertest. Frontend: React 18, Vite, Tailwind 3, react-router-dom 6, axios, react-icons, recharts, qrcode.react, html5-qrcode.

**Spec:** The master prompt plus the addendum in the conversation of 2026-10-10. Where they conflict, the addendum wins: it overrides spec section 3 (folders) and section 9 (seed).

## Global Constraints

- Every file in Addendum section D must exist with exactly that name and path. Any extra file must be listed and justified first (see "Approved extra files" below).
- No emojis anywhere: UI, code, comments, SQL seed, logs, commit messages, README. Icons come from `react-icons` only.
- Do not use or mention Redis, queues, caches, load balancers, microservices, WebSockets or Docker.
- Database access goes through Prisma only. The single exception is `SELECT ... FOR UPDATE` through `tx.$queryRaw` inside a transaction, with a comment explaining why.
- Money is stored as an Int in paise and shown in rupees through the shared `formatCurrency`.
- Ids are autoincrement Int. Tables are snake_case and Prisma models are PascalCase with `@@map`/`@map`.
- All payments are simulated. `payment_mode = 'SIMULATED'`, and every payment screen renders `<PaymentDisclaimer />` with the text "Demo payment: no real money is charged".
- Plain JavaScript ES modules (`"type": "module"`). No TypeScript.
- Controllers stay thin. Business rules live in services. Every protected route uses `auth` + `requireRole`.
- Error shape: `{ error: { code, message, details } }`. List shape: `{ data: [...], meta: { page, pageSize, total, totalPages } }`. Single shape: `{ data: {...} }`.
- Export names match file names: `events.service.js` exports `eventsService`, `events.controller.js` exports `eventsController`, `events.routes.js` exports `eventsRouter`, and `events.schema.js` exports named zod schemas.
- Demo password for every seeded account: `Password@123`.

## Review Focus

1. **Seed dates go stale.** If the SQL seed used fixed dates, the "upcoming" Spring Gala would be in the past by demo day. All seed dates are relative to `now()` (for example `now() + interval '21 days'`). The test in Task 1.2 (`verify.sql`) asserts that the gala starts in the future and that some memberships expire within 30 days.
2. **Concurrent bookings on a pooled Neon connection.** Twenty parallel transactions wait on the same row lock and can exceed Prisma's default 5s interactive-transaction timeout. Use `{ maxWait: 10000, timeout: 20000 }`. This is covered by `booking.concurrency.test.js`.
3. **Unique-violation inside an interactive transaction.** A P2002 error aborts the Postgres transaction, so the ALREADY_USED lookup must run after the transaction fails, not inside it. This is covered by `checkin.test.js` (parallel double scan).
4. **Large lists.** All admin lists (Members 100, Bookings 205, Ledger ~400) must paginate on the server. A client that passes `pageSize=10000` must be clamped to 100. This is tested in `auth.test.js` (Task 3.2 adds the pagination clamp assertion).
5. **Membership expiry boundary.** A member whose `expires_at` has passed but whose status still says ACTIVE (because the cron has not run yet) must still be treated as NOT active for pricing and check-in. This is covered by `pricing.test.js`.

## Decisions and Assumptions (one line each)

- Project root: the current workspace folder (`Student Organization System/`) plays the role of `clubflow/` in the manifest, so `frontend/`, `backend/`, `README.md` and `.gitignore` sit directly in it. Git is initialised there with one commit per phase. Commit messages have no emojis. The manifest check ignores `.claude/` and `docs/`.
- SQL seed: written by me (Task 1.2). You run it in Neon, then confirm.
- Tests: run against `TEST_DATABASE_URL`, a Neon branch of the seeded DB that you create.
- Execution: native, continuous. After you say proceed, I build Phases 1 to 8 in one go and pause only for the human steps (running the SQL in Neon and providing the DB URLs).
- `bcryptjs` is used instead of native `bcrypt`, so no native build step is needed on Windows. The hashes are compatible.
- Tests use `node:test` + `supertest`, so no vitest config file is needed. They run against `TEST_DATABASE_URL` (a Neon branch of the seeded DB). Each test creates its own fixtures with a unique suffix and deletes them afterwards.
- `transactions.source_id` is `VARCHAR(64)`. Linked rows store the source id as a string (for example `"42"`). Refunds store `"42:refund"`. Manual entries store `crypto.randomUUID()`. This keeps `UNIQUE(source_type, source_id)` meaningful for every case.
- Merchandise orders are paid at checkout (simulated): status `PAID`, and the MERCHANDISE ledger row is written in the same transaction. Admin then moves the order to `FULFILLED` or `CANCELLED`. Cancelling restores stock and writes a reversing `EXPENSE` row with source id `"<id>:refund"`.
- Booking cancellation is allowed before the event starts. It sets the booking to CANCELLED/REFUNDED and the ticket to CANCELLED, and writes a reversing ledger row (`type EXPENSE, category TICKETS, source BOOKING, source_id "<id>:refund"`).
- Joining requires studentId, department, year, phone and a tier. It creates the member profile, a PAID MembershipPayment, and a DUES ledger row in one transaction.
- "On track" for a fundraiser means `goalPct >= timePct - 10` and `taskPct >= timePct - 10`. Before the start date it is always on track.
- Leadership: activating a PRESIDENT position sets the user's role to ADMIN, and activating TREASURER sets it to TREASURER. Deactivating reverts to the highest role still granted by another active position, otherwise MEMBER (or VOLUNTEER if the user was a volunteer, which is stored in `previous_role`).
- Email: Nodemailer is used if `SMTP_HOST` is set. Otherwise the app logs `[mailer] would send to N recipients: <subject>`. An `email_logs` row is written either way.
- Currency is INR. Rupees are shown as `Rs 1,250.00` via `Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' })`.

## File responsibilities (locked decomposition)

**backend/src**
- `server.js`: loads env, starts `app.listen`, schedules `membershipExpiry.job.js`.
- `app.js`: helmet, cors(CLIENT_ORIGIN), json, `/uploads` static, `/api` -> `routes.js`, notFound, errorHandler. It exports `app` and does not listen, so supertest can import it.
- `routes.js`: mounts every module router under `/api`, plus `GET /api/health`.
- `config/env.js`: reads and validates `process.env` with zod and exports a frozen `env`.
- `config/prisma.js`: exports a single `prisma` client.
- `middleware/auth.js`: `auth` (requires a Bearer JWT and sets `req.user = { id, role, name, email }`) and `optionalAuth`.
- `middleware/requireRole.js`: `requireRole(...roles)` returns 403 FORBIDDEN.
- `middleware/validate.js`: `validate({ body, query, params })` uses zod, replaces `req.body/query/params` with the parsed values, and returns 400 VALIDATION_ERROR with details.
- `middleware/errorHandler.js`: maps ApiError, ZodError, Prisma P2002 -> 409 CONFLICT, P2025 -> 404 NOT_FOUND, MulterError -> 400, everything else -> 500.
- `middleware/notFound.js`: 404 ROUTE_NOT_FOUND.
- `middleware/upload.js`: `receiptUpload` uses multer disk storage in `backend/uploads`, a 5 MB limit, and accepts image/jpeg, image/png, image/webp and application/pdf.
- `middleware/rateLimiter.js`: `authLimiter` allows 20 requests per 15 minutes on `/auth/login` and `/auth/register`.
- `utils/apiError.js`: `class ApiError(status, code, message, details)` plus helpers `badRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`.
- `utils/asyncHandler.js`: wraps an async handler so rejections reach `next`.
- `utils/ticketToken.js`: `generateTicketToken()` returns `crypto.randomBytes(18).toString('base64url')` (24 chars).
- `utils/money.js`: `applyPercentDiscount(amountPaise, percent) -> { discount, final }` (integer math, rounded half up).
- `utils/mailer.js`: `sendBulkEmail({ to: string[], subject, text }) -> { status: 'SENT'|'LOGGED'|'FAILED', count }`.
- `utils/csv.js`: `toCsv(rows, columns)` with RFC 4180 quoting.
- `utils/pagination.js` (extra): `parsePagination(query) -> { page, pageSize, skip, take }` clamps pageSize to 1..100. `buildMeta(total, page, pageSize)`.
- `jobs/membershipExpiry.job.js`: `runMembershipExpiry(now = new Date()) -> { expired, remindersSent }` and `scheduleMembershipExpiry()` (cron `0 2 * * *`).

**Module pattern** (identical for all 17 modules):
```js
// events.routes.js
import { Router } from 'express';
import { auth, optionalAuth } from '../../middleware/auth.js';
import { requireRole } from '../../middleware/requireRole.js';
import { validate } from '../../middleware/validate.js';
import { eventsController } from './events.controller.js';
import { createEventSchema, listEventsQuery, idParam } from './events.schema.js';

export const eventsRouter = Router();
eventsRouter.get('/', optionalAuth, validate({ query: listEventsQuery }), eventsController.list);
eventsRouter.post('/', auth, requireRole('ADMIN'), validate({ body: createEventSchema }), eventsController.create);

// events.controller.js
import { asyncHandler } from '../../utils/asyncHandler.js';
import { eventsService } from './events.service.js';
export const eventsController = {
  list: asyncHandler(async (req, res) => res.json(await eventsService.list(req.query, req.user))),
  create: asyncHandler(async (req, res) => res.status(201).json({ data: await eventsService.create(req.body, req.user) })),
};
```
Modules with no routes of their own (`users`, `tickets`) still export a router. It can be empty or small (for example `GET /api/users/search?q=` for assignee pickers, ADMIN/TREASURER only, and `GET /api/tickets/:token/qr` is not needed, so tickets exposes `GET /api/tickets/my`, which aliases bookings with tickets).

**frontend/src**
- `api/axiosInstance.js`: `baseURL = import.meta.env.VITE_API_URL`. It attaches `Authorization` from the token store. A 401 response clears the token and redirects to `/login?next=...`.
- `api/<resource>.api.js`: exports a single object, for example `eventsApi = { list(params), get(id), create(body), update(id, body), publish(id), stats(id), bookings(id, params), checkins(id, params) }`. Every function returns `res.data`.
- `context/AuthContext.jsx`: `{ user, token, login(email, pw), register(body), logout(), refreshMe(), hasRole(...roles) }`.
- `context/ToastContext.jsx`: `{ toast.success(msg), toast.error(msg) }`. It renders `ui/Toast.jsx`.
- `hooks/useFetch.js`: `useFetch(fn, deps) -> { data, meta, loading, error, reload }`.
- `hooks/useDebounce.js`: `useDebounce(value, 300)`.
- `routes/routeConfig.jsx`: an array of `{ path, element, roles?, layout: 'public'|'app' }`. `routes/ProtectedRoute.jsx` sends unauthenticated users to /login and users with the wrong role to `/`.
- `utils/formatCurrency.js`: `formatCurrency(paise)`, `toPaise(rupeesString)`. `utils/formatDate.js`: `formatDate`, `formatDateTime`, `daysUntil`. `utils/constants.js`: role, status and badge-color maps, plus `NAV_ITEMS` per role.

errorHandler core:
```js
export function errorHandler(err, req, res, next) {
  if (err instanceof ApiError) return send(res, err.status, err.code, err.message, err.details);
  if (err instanceof ZodError) return send(res, 400, 'VALIDATION_ERROR', 'Invalid input', err.flatten());
  if (err.code === 'P2002') return send(res, 409, 'CONFLICT', 'Duplicate record', { target: err.meta?.target });
  if (err.code === 'P2025') return send(res, 404, 'NOT_FOUND', 'Record not found');
  if (err.name === 'MulterError') return send(res, 400, 'UPLOAD_ERROR', err.message);
  console.error(err);
  return send(res, 500, 'INTERNAL_ERROR', 'Something went wrong');
}
```

### Task 4.2: Booking transaction with row lock

**Files:** `modules/bookings/*`, `modules/tickets/*`, `utils/ticketToken.js`, `tests/pricing.test.js`, `tests/booking.concurrency.test.js`.

**Interfaces:** `bookingsService.create({ eventId, userId }) -> { booking, ticket }`, `bookingsService.listMine(userId, query)`, `bookingsService.cancel(bookingId, user)`, `ticketsService.issue(tx, bookingId) -> ticket`, and `pricingFor(eventRow, member, now) -> { price, isMemberPrice, discount }` (exported from bookings.service for the tests).

```js
export async function createBooking({ eventId, userId }) {
  const now = new Date();
  return prisma.$transaction(async (tx) => {
    // Prisma cannot express SELECT ... FOR UPDATE. Locking the event row serialises
    // concurrent bookings for this event so the seat count below cannot go stale.
    const [event] = await tx.$queryRaw`
      SELECT id, status, capacity, start_at, end_at, booking_opens_at, booking_closes_at, member_price, non_member_price
      FROM events WHERE id = ${eventId} FOR UPDATE`;
    if (!event) throw notFound('Event not found');
    if (event.status !== 'PUBLISHED') throw conflict('EVENT_NOT_OPEN', 'This event is not open for booking');
    if (now < event.booking_opens_at || now > event.booking_closes_at || now > event.end_at)
      throw conflict('BOOKING_WINDOW_CLOSED', 'Booking is not open right now');
    const existing = await tx.booking.findFirst({ where: { eventId, userId, status: 'CONFIRMED' } });
    if (existing) throw conflict('ALREADY_BOOKED', 'You already have a ticket for this event');
    const booked = await tx.booking.count({ where: { eventId, status: 'CONFIRMED' } });
    if (booked >= event.capacity) throw conflict('SOLD_OUT', 'This event is sold out');
    const member = await tx.member.findUnique({ where: { userId } });
    const { price, isMemberPrice, discount } = pricingFor(event, member, now);
    const booking = await tx.booking.create({ data: { eventId, userId, priceAtBooking: price, discountApplied: discount, isMemberPrice, status: 'CONFIRMED', paymentStatus: 'PAID', paymentMode: 'SIMULATED' } });
    const ticket = await ticketsService.issue(tx, booking.id);
    if (price > 0) await tx.transaction.create({ data: { type: 'INCOME', category: 'TICKETS', amount: price, eventId, sourceType: 'BOOKING', sourceId: String(booking.id), description: `Ticket #${booking.id}`, occurredAt: now, recordedById: userId } });
    return { booking, ticket };
  }, { maxWait: 10000, timeout: 20000 });
}
```
`pricingFor`: an active member pays `member_price` and `discount = non_member_price - member_price`. Everyone else pays `non_member_price` and `discount = 0`. The request body never contains a price: `createBookingSchema = z.object({}).strict()`, so `{ price: 1 }` is rejected with 400.

### Task 5.1: Verify endpoint

**Files:** `modules/checkins/*`, `tests/checkin.test.js`.

**Interfaces:** `checkinsService.verify({ eventId, token, staffId }) -> { result, attendee: { name, email } | null, membership: { isActive, tier, expiresAt } | null, checkedInAt, ticketId }` with `result` in `VALID | ALREADY_USED | WRONG_EVENT | INVALID | CANCELLED`. Every scan outcome returns HTTP 200 with `data.result`, and only auth or validation errors are non-200. This keeps the scanner logic to a single switch on `data.result`.

```js
async verify({ eventId, token, staffId }) {
  const ticket = await prisma.ticket.findUnique({ where: { token }, include: { booking: { include: { user: { include: { member: { include: { tier: true } } } } } }, checkIn: true } });
  if (!ticket) return { result: 'INVALID' };
  const base = describe(ticket);
  if (ticket.booking.eventId !== eventId) return { ...base, result: 'WRONG_EVENT' };
  if (ticket.status === 'CANCELLED' || ticket.booking.status !== 'CONFIRMED') return { ...base, result: 'CANCELLED' };
  if (ticket.status === 'USED') return { ...base, result: 'ALREADY_USED', checkedInAt: ticket.checkIn?.checkedInAt };
  try {
    const checkIn = await prisma.$transaction(async (tx) => {
      // Guarded update: only one concurrent scan can flip VALID -> USED.
      const { count } = await tx.ticket.updateMany({ where: { id: ticket.id, status: 'VALID' }, data: { status: 'USED' } });
      if (count === 0) throw conflict('ALREADY_USED', 'Ticket already used');
      return tx.checkIn.create({ data: { ticketId: ticket.id, checkedInById: staffId, checkedInAt: new Date(), membershipVerifiedActive: base.membership?.isActive ?? false } });
    });
    return { ...base, result: 'VALID', checkedInAt: checkIn.checkedInAt };
  } catch (err) {
    // The unique index on check_ins.ticket_id is the final guard. Postgres aborts the
    // transaction on a unique violation, so the original check-in is read afterwards.
    if (err.code !== 'P2002' && err.code !== 'ALREADY_USED') throw err;
    const original = await prisma.checkIn.findUnique({ where: { ticketId: ticket.id } });
    return { ...base, result: 'ALREADY_USED', checkedInAt: original?.checkedInAt };
  }
}
```
